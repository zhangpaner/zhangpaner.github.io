Qt 入门（一）：环境搭建与开发工具链

发表于2026-09-24|更新于2026-09-24|Qt开发

先认识 Qt 开发环境

Qt 不是一个单独的 IDE。写一个 Qt 程序通常需要四样东西：Qt 库、C++ 编译器、构建工具，以及编辑和调试工具。Qt Creator 是 IDE；MinGW、MSVC、Clang 或 GCC 才是实际编译 C++ 的工具链；CMake 负责生成构建规则；Qt 库提供窗口、网络、文件等 API。

初学桌面开发建议采用 Qt 6 + Qt Creator + CMake。Qt 官方在线安装器可以交互选择 Qt 版本、模块和开发工具。安装时优先选择一个稳定发布版、与操作系统匹配的桌面套件，以及 CMake/Ninja 等构建工具。不要只勾选 Qt 库而漏掉编译器。

Windows

Windows 上先决定编译器：

  • MSVC：需要安装对应版本的 Visual Studio 或 Visual Studio Build Tools，并选择 C++ 桌面开发组件。优点是与微软调试器和生态集成好。
  • MinGW：适合希望使用 GCC 工具链的初学者。应使用 Qt 安装器提供或明确兼容的 MinGW 版本，避免随便从其他地方下载一个不同版本来混用。

在 Qt 安装器中勾选相应的 Qt 桌面套件（例如 MSVC 或 MinGW 套件）和 Qt Creator。一个 MSVC Kit 不能拿 MinGW 编译器构建，反之亦然。

macOS 与 Linux

macOS 通常使用 Xcode Command Line Tools 提供的 Clang；可用 xcode-select --install 安装。Linux 通常使用发行版 GCC/Clang，并先安装基础编译工具和 CMake。发行版仓库里的 Qt 版本可能与官方在线安装器中的版本不同；团队项目要统一 Qt 版本和工具链来源。

无论平台，Qt 库、编译器的目标架构和 ABI 都必须匹配。例如不能用 ARM Qt 套件链接 x86_64 编译产物，也不能把 Debug 编译器套件与另一套 Qt 库随意混用。

检查 Qt Creator 的 Kit

启动 Qt Creator 后检查 Preferences/设置 → Kits（不同版本菜单名称可能略有差异）：

  1. Qt Versions 能找到已安装的 Qt 版本。
  2. Compilers 能找到 C++ 编译器。
  3. CMake 能找到 CMake 可执行文件。
  4. Kits 页面将 Qt 版本、编译器、调试器和生成器组合成一个可用 Kit。

新建项目时，选择 Desktop Kit。Kit 不完整或提示无效时，先核对编译器安装，再重新扫描 Qt 版本；不要通过复制 DLL 或改 PATH 来掩盖工具链不匹配。

Windows 下可在对应开发者终端运行 cl（MSVC）或 g++ --version（MinGW）；macOS/Linux 可运行 clang++ --version 或 g++ --version。Qt Creator 运行成功比单独看到版本号更重要，因为这验证了 Qt、编译器和构建生成器确实配合工作。

常见问题

  • 找不到 Qt：检查是否安装了当前 Kit 对应的 Qt 桌面套件，并且项目选择了正确 Kit。
  • 构建目录里残留旧配置：切换编译器或 Qt 版本后，使用 Qt Creator 的 Clean/Reconfigure，必要时删除独立的构建目录再配置。CMake 缓存会记住旧编译器路径。
  • 运行时缺少动态库：这通常是部署问题，不代表开发环境没有装好；开发机可能通过 Qt Creator 配好的环境变量找到了库。
  • 新手该选 Qt 5 还是 Qt 6：新项目优先 Qt 6。维护旧项目时再按项目依赖和目标平台选择相应版本。

环境确认后，后续教程都用 CMake 管理 Qt 6 项目。安装入口和注意事项见 Qt 官方安装指南 与 Qt Creator 安装指南。
