JavaScript 进阶：Promise 链、错误处理与并发控制

发表于2026-09-24|更新于2026-09-24|JavaScript进阶
|字数总计:715|阅读时长:2分钟|阅读量:

Promise 表示未来完成的结果

Promise 有三种状态：pending、fulfilled、rejected。状态一旦确定就不会再改变。then 返回新的 Promise，因此可以把异步步骤连成链。

每个 then 回调的返回值会决定下一个 Promise：普通值会成为成功结果；返回 Promise 会等待它；抛出异常会使链进入失败状态。忘记 return response.json() 是常见错误，会令后续拿不到解析后的数据。

finally 和错误恢复

finally 适合释放加载状态或资源，不会接收原结果。若它正常完成，原来的成功或失败结果会继续传递；如果它抛错，则链会改为失败。

catch 也可以恢复错误：返回普通值后，后续链会继续成功状态。如果错误不能处理，就重新抛出，或让它继续传递给调用者。

选择正确的组合方法

  • Promise.all：全部成功才成功；有一个失败就立即失败。适合结果缺一不可的并行读取。
  • Promise.allSettled：等待全部结束，逐项返回成功或失败状态。适合批量操作并汇总每项结果。
  • Promise.race：第一个完成（成功或失败）者决定结果，常用于竞争超时。
  • Promise.any：第一个成功者决定结果；全部失败时以 AggregateError 拒绝。

注意，Promise 组合不会自动取消仍在进行的请求。race 超时后，慢请求依然可能继续消耗资源。

限制并发数量

共享的 next 在同一 JavaScript 线程里每次递增是同步完成的，因此每个索引只会分配一次。生产实现还应明确单项失败时整体停止还是继续收集错误，并检查 limit 是正整数。

Promise 负责表达异步结果，不会自动把耗时 CPU 计算移到另一个线程。大量同步计算仍会阻塞当前线程；浏览器中可考虑 Web Worker。网络等异步 I/O 的并发应按服务端限制和资源能力控制。
