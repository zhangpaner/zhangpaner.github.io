Qt 进阶（七）：网络请求与异步界面

为什么网络请求不能阻塞界面

GUI 主线程负责事件循环。若用阻塞式调用等待服务器，绘制、输入和窗口移动都无法及时处理，看起来像程序卡死。Qt Network 的 QNetworkAccessManager 采用异步请求：调用立即返回，响应完成后通过信号通知程序。

在 CMake 中加入 Network：

GET 请求示例

QNetworkReply 也是 QObject；请求完成后应释放它，常用 deleteLater()。将管理器作为长期存在的成员，可以复用连接配置和缓存策略。示例中的回调以窗口为接收对象，窗口销毁后连接会断开；真实项目还要定义取消请求和关闭窗口时的策略。

HTTP 状态码、JSON 和错误

网络错误和 HTTP 状态码是两个层面的信息：DNS、TLS、超时等会反映在 reply->error()；服务器返回 404 或 500 时请求仍可能成功收到了 HTTP 响应，需读取 HttpStatusCodeAttribute 判断业务结果。对 JSON 响应使用 QJsonDocument::fromJson() 并检查解析错误，不要假设服务器永远返回正确格式。

POST 请求应设置正确的 Content-Type，并对用户输入、认证信息和失败重试做清晰处理。认证令牌不要写死在源码或日志中。TLS 验证错误不能通过无条件忽略证书错误来“修复”。

超时、取消和防止过期结果

页面切换或搜索词变化时，旧请求的响应可能晚于新请求到达。保存当前请求标识或 URL，只有响应仍对应当前页面时才更新界面。必要时调用 abort() 取消旧 QNetworkReply。设置合理超时（可通过定时器或 Qt 支持的超时配置完成），并为加载中、失败和空结果设计界面状态。

线程说明

QNetworkAccessManager 在自己的线程/事件循环中异步工作，并不需要为普通 HTTP 请求另外创建线程。不要在主线程调用阻塞网络 API。若完成回调要处理大量数据，可把计算任务移到工作线程；回调更新 QWidget 时必须回到 GUI 线程。

模块细节见 Qt Network。
