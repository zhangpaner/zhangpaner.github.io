JavaScript 进阶：ES 模块、实时绑定与动态导入

发表于2026-09-24|更新于2026-09-24|JavaScript进阶
|字数总计:628|阅读时长:2分钟|阅读量:

静态 import 描述模块依赖

ES Module（ESM）使用 export 暴露接口，用 import 引入接口。静态导入必须位于模块顶层，方便运行时或打包工具在执行前分析依赖关系。

命名导出可以有多个，默认导出每个模块最多一个。导入名称是本地绑定，改名不会改动导出端名称。

导入的是实时绑定

ESM 的导入绑定与导出模块关联，不是导入时复制出来的快照。导出模块可以更新它自己的绑定，读取方后续会观察到新值；导入方不能给导入绑定重新赋值。

不要把模块变量当作可由消费者任意改写的共享状态。通过导出函数或明确的状态接口管理修改，更容易追踪数据流。

动态导入和按需加载

import() 是运行时表达式，返回 Promise，可按条件加载模块，常用于路由分包或低频功能：

导入失败会使 Promise 拒绝，应在合适位置捕获并呈现错误。动态导入不等于脚本总是只加载一次或网络请求一定发生；具体缓存和打包拆分由运行环境决定。

循环依赖要谨慎

如果模块 A 依赖 B，B 又依赖 A，形成循环依赖。ESM 会先建立模块绑定再执行模块代码，但执行顺序和读取时机可能让尚未初始化的绑定触发错误。可以把双方共用的类型或纯函数抽到第三个模块，或调整依赖方向，避免模块初始化阶段互相访问未准备好的状态。

ESM 与 CommonJS

Node.js 项目需要通过文件扩展名、package.json 中的 type 等方式确定模块格式；浏览器通常通过 <script type="module"> 加载 ESM。不同工具链对 CommonJS 与 ESM 的互操作规则并不完全一样。检查项目实际运行环境和构建工具，再决定导入写法。
