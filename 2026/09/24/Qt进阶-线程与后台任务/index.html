Qt 进阶（八）：线程与后台任务

发表于2026-09-24|更新于2026-09-24|Qt开发
|字数总计:713|阅读时长:2分钟|阅读量:

GUI 线程只做轻量工作

Widgets 及其子类不是线程安全的，应只在 GUI 线程创建和操作。耗时计算、文件扫描或阻塞工作若运行在 GUI 线程，会阻塞事件循环。后台对象通过信号把结果传回 GUI 线程更新界面。

常见模式是将 worker QObject 移入 QThread，而不是把业务槽都写进 QThread 子类。QThread 对象本身仍属于创建它的线程；真正执行任务的是它管理的线程。

Worker + QThread 模式

跨线程 Auto/Queued 连接会把调用排入接收对象所属线程的事件队列，因此进度条槽在 GUI 线程执行。任务结束时退出线程并安排对象清理。若窗口可能在任务运行时关闭，必须先请求取消并等待线程结束，不能让窗口析构后还留着无主线程。

线程亲和性和事件循环

QObject 有 thread affinity；排队信号槽和定时器事件会在对象所属线程的事件循环处理。moveToThread() 只能移动没有父对象的对象，子对象会一起移动。移入线程后，不能随意从 GUI 线程直接调用 worker 的状态函数并同时读写共享数据；应通过信号槽传递消息，或明确使用锁保护共享状态。

如果 worker 需要 QTimer、QTcpSocket 等事件驱动对象，目标线程必须有运行的事件循环；耗时槽若持续阻塞该事件循环，这些异步事件也无法处理。

什么时候用 QtConcurrent

对于没有复杂对象生命周期的独立计算，QtConcurrent::run() 和 QFutureWatcher 可以减少线程管理代码。任务需要长期事件循环、状态消息或可控生命周期时，worker-object 模式更直观。大量短任务通常使用线程池，而不是每个任务创建一条线程。

常见错误

  • 后台线程直接调用 QLabel::setText()：通过信号把结果交回 GUI 线程。
  • worker 有 parent 仍调用 moveToThread()：先让它成为无父对象，再移动。
  • 线程还在运行就销毁 QThread：设计停止/取消流程，并在析构前等待结束。
  • 使用 DirectConnection 跨线程更新界面：接收代码会在发射信号的线程执行，GUI 对象访问不安全。

详见 Threads and QObjects。
