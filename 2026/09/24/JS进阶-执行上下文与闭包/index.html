JavaScript 进阶：执行上下文、作用域与闭包

发表于2026-09-24|更新于2026-09-24|JavaScript进阶
|字数总计:703|阅读时长:2分钟|阅读量:

先理解代码运行时的“环境”

JavaScript 执行代码时，需要知道有哪些变量、函数，以及标识符应该到哪里查找。引擎会为正在执行的代码建立执行上下文，并维护相应的词法环境。可以把它理解为一次执行所需的变量记录和外层环境引用。

函数的作用域在定义时就确定了，而不是在调用时根据调用者临时决定。这叫词法作用域。

调用 fn 时，outer 已经执行完毕，但 inner 仍能读取定义位置的 name。函数对象保留了访问其词法环境的能力；这个现象就是闭包的核心。

闭包不是特殊语法

“闭包”常被描述成“函数加上它能访问的外部变量”。闭包不会把外部变量拍成静态快照；只要闭包仍可访问，相关绑定就需要继续存在。

外部代码无法直接写 count，只能通过返回的接口读写它。这种封装适合管理组件状态、生成带私有状态的回调，以及实现缓存。

常见误区与内存

闭包本身不会自动造成内存泄漏。只有当某个长生命周期对象仍持有闭包，而闭包又引用了不再需要的大对象时，这些对象才可能一直无法回收。事件监听器、定时器和订阅回调是常见持有者；不再使用时应移除监听、清除定时器或取消订阅。

闭包捕获的是词法绑定，不是“创建函数那一刻的值”。如果变量后来被修改，调用闭包时通常会看到修改后的值。

用闭包把状态限制在模块内部；用函数工厂按参数生成行为不同的函数；用缓存记住计算结果时要控制容量和生命周期。遇到闭包问题，先问：函数在哪里定义？它引用的外部绑定由谁继续持有？
