项目结构

建立一个空目录，创建 CMakeLists.txt 和 main.cpp：

在 CMakeLists.txt 中声明语言标准、寻找 Qt Widgets 模块并连接目标：

find_package 加载模块信息，target_link_libraries 把 Widgets 依赖加到应用目标。把依赖写在目标上比使用全局 include 路径、库路径更可靠。

写入口函数

QApplication 管理 Widgets 应用的全局状态和事件分发，应在创建窗口控件前构造。QLabel 此处既显示文字，也是顶层窗口。调用 show() 后窗口才可见；app.exec() 启动事件循环，程序在这里响应绘制、鼠标和键盘等事件。

在 Qt Creator 中构建

用 File → Open File or Project 打开 CMakeLists.txt，选择前一篇配置好的 Desktop Kit。Qt Creator 会先配置 CMake，再构建目标。修改代码后按 Build，再按 Run。源码目录和构建目录应分开，例如 build/Qt_6_..._Debug；不要把生成的中间文件提交到 Git。

也可以在终端从项目根目录构建：

这里假设当前终端能找到匹配的 Qt CMake 包。若找不到，可以使用 Qt 安装目录中对应 Kit 的 qt-cmake，或显式设置 CMAKE_PREFIX_PATH。Windows 多配置生成器（例如 Visual Studio）通常在构建时选择配置：

Qt 的宏和生成步骤

Qt 的信号槽和元对象能力依赖 Meta-Object Compiler（moc）扫描带有 Q_OBJECT 的类。使用 qt_standard_project_setup() 后，Qt 的 CMake 集成会为常见情形启用自动 moc、资源和 UI 处理。如果 CMake 项目没有使用 Qt 的标准设置，就需要检查 AUTOMOC 等属性是否正确打开。
